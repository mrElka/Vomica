# Инвентарь: как подключить UI

Инвентарь состоит из трёх видов ячеек:

- **слоты экипировки** — шлем, броня, оружие, щит. Их всегда четыре;
- **хотбар** — быстрая панель;
- **рюкзак** — основное хранилище.

Сколько ячеек в хотбаре и рюкзаке — не зашито. Начальное количество задаётся в
инспекторе `PlayerInventory` (поля **Hotbar Size** и **Backpack Size**), а во время игры
ячейки можно добавлять и убирать из кода. Поэтому UI не должен рассчитывать на
конкретное число ячеек — сетку строит `InventoryGridView` (раздел 2).

Вся логика уже в `PlayerInventory` (висит на игроке). От UI нужно нарисовать ячейку
и сказать, какой слот она показывает.

## 1. Префаб ячейки

1. Сделай объект ячейки на Canvas: фон, внутри `Image` для иконки и `Text` для количества.
2. Повесь на него компонент **`InventorySlotView`**.
3. Перетащи в поля:
   - **Icon** — `Image`, где показывать иконку предмета;
   - **Empty Sprite** — картинка пустой ячейки (можно оставить пустым — иконка спрячется);
   - **Count Text** — `Text` для количества (виден только при 2 и больше);
   - **Picked Highlight** — объект-рамка, который включается, когда предмет «взят».
4. Ячейке нужен компонент, который ловит клики (`Image` с включённым **Raycast Target**),
   а на сцене — `EventSystem`.
5. Сохрани как префаб. Поле **Slot Id** в префабе оставь **пустым**.

Ячейка сама находит инвентарь, сама перерисовывается при изменениях и сама обрабатывает клики.

## 2. Хотбар и рюкзак: `InventoryGridView`

Ячейки хотбара и рюкзака не расставляются руками.

1. Создай контейнер на Canvas и повесь на него `GridLayoutGroup` (для рюкзака) или
   `HorizontalLayoutGroup` (для хотбара) — они отвечают за раскладку.
2. Повесь на контейнер **`InventoryGridView`**:
   - **Kind** — `Hotbar` или `Backpack`;
   - **Slot Prefab** — префаб ячейки из раздела 1;
   - **Container** — куда спавнить ячейки (пусто — сам объект).

При старте сетка создаст столько ячеек, сколько сейчас слотов, и выставит им id.
Когда из кода добавят или уберут ячейки, сетка пересоберётся сама.

## 3. Слоты экипировки

Эти четыре ячейки ставятся на макет вручную: перетащи префаб ячейки и впиши **Slot Id**.

| Slot Id | Что это | Что туда можно положить |
|---|---|---|
| `helmet` | надетый шлем | предметы с Category = Helmet |
| `armor` | надетая броня | Category = Armor |
| `weapon` | оружие в руке | Category = Weapon (кроме щитов) |
| `shield` | щит в левой руке | Category = Weapon, Weapon Sub Category = Shield |

Если id написан с ошибкой, в консоли будет предупреждение с именем объекта.

## 4. Id ячеек хотбара и рюкзака

Id выдаются по порядку с нуля: `hotbar_0`, `hotbar_1`, … и `inv_0`, `inv_1`, …
Сколько их сейчас — `inventory.HotbarSize` и `inventory.BackpackSize`, полный список —
`inventory.GetSlotIds(InventorySlotKind.Backpack)`.

В коде лучше собирать id через константы, а не строками:
`InventorySlotIds.Helmet`, `InventorySlotIds.Hotbar(3)`, `InventorySlotIds.Backpack(10)`.

Цифры **1–9** на клавиатуре работают с первыми девятью ячейками хотбара:
клавиша **1** — `hotbar_0`, клавиша **9** — `hotbar_8`. Если хотбар меньше девяти,
лишние цифры ничего не делают; ячейки после девятой доступны только мышью.

## 5. Что делает игрок

| Действие | Результат |
|---|---|
| ЛКМ по ячейке с предметом | предмет «взят», включается подсветка |
| ЛКМ по другой ячейке | предмет переносится; если там что-то лежит — меняются местами |
| Shift + ЛКМ | надеть предмет в его слот экипировки или снять надетый в первую свободную ячейку |
| ПКМ | отменить «взятие» |
| Цифры 1–9 | надеть предмет из ячейки хотбара с этим номером |

Положить предмет не в свой слот нельзя: шлем не встанет в `weapon`, меч — в `helmet`.
Такой перенос просто не произойдёт.

## 6. Откуда ячейка берёт картинку и название

Каждый предмет — это ассет `EquipmentItem` (Create → Equipment → Equipment Item).
Ячейка показывает его поле **Icon**. Для панели описания пригодятся:

| Поле предмета | Зачем UI |
|---|---|
| **Item Id** | уникальная строка, по ней предмет хранится в инвентаре и в сохранении. Не меняй у уже выданных предметов — сохранения перестанут их находить |
| **Display Name**, **Description** | название и описание |
| **Icon** | иконка в ячейке |
| **Category** / **Weapon Sub Category** | в какой слот экипировки предмет надевается |
| **Max Stack** | сколько штук в одной ячейке (для экипировки 1) |
| **Stats** | полоски в панели информации |

Чтобы предмет вообще существовал в игре, он должен быть добавлен в список
`EquipmentDatabase` (`Assets/Scripts/CharEqiup/Items/EquipmentDatabase.asset`).

Сейчас в базе такие id: `weapon_0` кинжал, `weapon_1` булава, `weapon_2` меч,
`weapon_3` молот, `weapon_4` дубина, `weapon2_1` двуручный меч,
`helm_0` дырявое ведро, `helm_1` шлем T1, `helm_test`, `helm_test2`.

## 7. Работа из кода

```csharp
PlayerInventory inv = PlayerInventory.Instance;

InventorySlot slot = inv.GetSlot("hotbar_0");
// slot.IsEmpty, slot.Item (EquipmentItem), slot.ItemId ("none" если пусто), slot.Count, slot.Kind

inv.Move("inv_3", "weapon");     // перенос / обмен, false — нельзя
inv.QuickEquip("hotbar_2");      // как Shift+клик
inv.Unequip("helmet");           // снять в свободную ячейку
inv.CanPlace("helmet", item);    // подсветить ячейку при перетаскивании
inv.AddItem("weapon_1");         // выдать предмет (лут, магазин)
inv.RemoveItem("inv_5");         // выбросить стопку

inv.OnSlotChanged += slotId => { /* перерисовать одну ячейку */ };
inv.OnInventoryChanged += () => { /* перерисовать всё — после загрузки */ };
```

### Добавление и удаление ячеек

```csharp
// +9 ячеек рюкзака (например, надели сумку). Возвращает id новых ячеек
IReadOnlyList<string> newIds = inv.AddSlots(InventorySlotKind.Backpack, 9);

// Задать точное количество
inv.SetSize(InventorySlotKind.Hotbar, 6);

inv.OnLayoutChanged += () => { /* число ячеек изменилось — пересобрать свой UI */ };
```

- Новые ячейки добавляются в конец: если было `inv_0`…`inv_26`, появятся `inv_27`…
- При уменьшении предметы из убираемых ячеек переезжают в свободные. Если места нет,
  `SetSize` вернёт `false` и ничего не изменит.
- Слоты экипировки так не меняются: их всегда четыре.
- `InventoryGridView` подписан на `OnLayoutChanged` сам, руками ничего делать не надо.

Если нужен свой UI вместо `InventoryGridView` (например, с перетаскиванием иконки),
строй ячейки по списку id:

```csharp
foreach (string id in inv.GetSlotIds(InventorySlotKind.Backpack))
{
    InventorySlotView cell = Instantiate(slotPrefab, gridParent);
    cell.SlotId = id;
}
```

## 8. Статус SelectedItems

Что сейчас надето, одной строкой:

```csharp
string json = PlayerInventory.Instance.SelectedItemsJson;
// {"helmet":"none","armor":"none","weapon":"weapon_2","shield":"none"}

string weapon = PlayerInventory.Instance.GetSelected("weapon");   // "weapon_2" или "none"
var all = PlayerInventory.Instance.SelectedItems;                  // словарь slot -> itemId

PlayerInventory.Instance.OnSelectedItemsChanged += json => { /* обновить куклу персонажа */ };
```

Значения — это **Item Id** предметов, `"none"` — слот пуст. В инспекторе на игроке тот же
статус виден в блоке «Статус (только чтение)».

## 9. Сохранение

Инвентарь сохраняется сам при каждом изменении и при выходе, загружается при старте сцены.
Переживает и перезапуск игры, и смерть игрока.

- Файл: `Application.persistentDataPath/inventory.json`
  (на Windows: `C:\Users\<имя>\AppData\LocalLow\<Company>\<Product>\inventory.json`).
- Сохраняются предметы **и количество ячеек**: если во время игры добавили ячейки
  через `AddSlots`, после перезапуска они останутся.
- Если в сохранении ячеек больше, чем в **Hotbar Size** / **Backpack Size** инспектора,
  берётся число из сохранения. Уменьшить можно только через `SetSize` или сбросом сохранения.
- Если файла нет — выдаётся **Starting Items** из инспектора `PlayerInventory`.
- Сбросить: ПКМ по компоненту `PlayerInventory` в инспекторе → **«Сбросить сохранение
  инвентаря»**, или удалить файл.
- Галка **Use Save** выключает сохранение — удобно, когда тестируешь стартовый набор.
